# Perfil profesional en GitHub

Revisión de mi propio perfil (`github.com/GabTS75`), con lo que ya tengo bien y "lo que me queda por mejorar" antes de usarlo activamente en procesos de selección.

## Lo que ya funciona

- **Bio clara:** mi README de perfil ya cuenta mi historia real — *mi origen en los 90, el giro profesional, y por qué he vuelto a la tecnología*. Es honesta y se diferencia de un perfil genérico.
- **Repositorios con nombre identificable:** sigo un patrón consistente (`Proyecto3-Katas-Python`, `Proyecto4-SQL`, `Proyecto5-noSQL`...), además de una breve descripción de cada uno de ellos, lo que facilita que cualquiera entienda de un vistazo qué contiene cada uno sin tener que abrirlo.
- **Variedad real de tecnologías:** Python, JavaScript, SQL, NoSQL, scripting de automatización (Bash/PowerShell) — *Demuestro que mi perfil no se queda en un único lenguaje, cosa que como "perfil junior" con "background no tradicional" juega a mi favor*.

## Lo que voy a mejorar

- **Repositorio `VectorSec`:** este es, con diferencia, mi proyecto más completo hasta la fecha, y todavía no está terminado con un README principal a la altura del resto de documentación que he generado durante el proyecto. Es la primera tarea pendiente que tengo, incluso antes de tocar algo más.
- **README de cada proyecto individual:** algunos de mis repositorios más antiguos (*los primeros Proyectos del ciclo*) tienen README más simples y escuetos que los que he aprendido a escribir ahora. Los iré revisando y ampliando con el mismo criterio que he usado en `VectorSec`: **qué es, qué problema resuelve, qué aprendí**.
- **Pin de repositorios:** quiero fijar en mi perfil los *4-6 proyectos que mejor me representan** (*empezando por* `VectorSec`) en vez de dejar que se mezclen con pruebas o ejercicios.
